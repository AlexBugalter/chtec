# Чтец

Текущая сборка: **0.5.1** (постоянный фон исходника, связанные области и пространственный экспорт).

Настольное приложение на Python для превращения рукописных фотографий и сканов
в редактируемый цифровой текст. Интерфейс на русском, обработка моделей — через
локальный сервер LM Studio / Unsloth или выбранный облачный API. Телеметрии нет.
При выборе облака изображения и текст передаются указанному поставщику.

## Запуск в Windows

После установки откройте **start.bat** двойным щелчком или выполните:

```powershell
cd chtec
.\.venv\Scripts\python.exe -m chtec
```

На другом компьютере установите Python 3.11+ и выполните `install.bat`, затем
`start.bat`. На этапе установки нужен интернет для загрузки библиотек; для локального распознавания интернет не нужен. Модель скачайте заранее в выбранном сервере.
Для установки вручную:

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
.\.venv\Scripts\python.exe -m chtec
```

Из любого терминала после установки доступна команда `chtec`.
Можно передать имена входных файлов: `python -m chtec scan.pdf photo.jpg`.

### Остановка и закрытие

Откройте `stop.bat` двойным щелчком или выполните `.\stop.bat` из папки проекта.
Он запрашивает обычное закрытие запущенных экземпляров Чтеца. При несохранённых
изменениях подтвердите действие в окне приложения. Если идёт обработка, приложение
сначала останавливается после текущего запроса, затем закрывается.

Для зависшего процесса используйте `.\stop.bat /force` — это немедленное завершение
с потерей несохранённой сессии. Другие программы Python батник не завершает.
Прямой эквивалент: `powershell -NoProfile -ExecutionPolicy Bypass -File tools/stop_app.ps1`;
добавьте `-Force` для принудительного завершения.

Ctrl+C в консоли теперь запрашивает остановку обработки через событие Qt; исключение
больше не должно прерывать применение ответа модели. Внизу окна показывается время
ожидания. Во время OCR текст появляется после полного ответа модели, а не по токенам.

## Выделение и расположение текста

Нажмите **Распознать с расположением**: локальная модель предложит блоки с текстом,
координатами и углами. Проверьте предложение перед применением. Пунктирные рамки
обозначают непроверенную геометрию; правка текста сама её не подтверждает.

Во вкладке **Как в оригинале** фото и цифровая страница расположены рядом.
Фото хранится в отдельном фоновом слое: выделение и перестроение зон не удаляют его.
Щелчок по области с любой стороны подсвечивает тот же блок с другой стороны.
Колесо меняет масштаб, перетаскивание перемещает страницу. Выделение рамкой
выбирает пересекающиеся блоки. **Уточнить выбранный блок** читает увеличенный
фрагмент исходника, разворачивая его для OCR; его место и исходный угол сохраняются.

Двойной щелчок или правая кнопка → **Редактировать** открывает текст блока и угол.
Меню также содержит копирование, вставку, удаление текста, отмену, подтверждение
геометрии, изменение порядка чтения и снятие привязки с сохранением текста.
Кнопкой **Перепривязать** можно перенести выбранный блок в новую обведённую область.

Для старых результатов без координат: во вкладке **Текст и фрагменты** выделите
слова и область на фото, затем нажмите **Привязать выделенный текст к участку**.
Остальной текст сохранится без координат. Либо повторите OCR с расположением.
После появления блоков сводный текст защищён от глобальной правки; правьте
выбранный блок, чтобы не разрушать координаты. Текст без разметки остаётся редактируемым.

**JSON** сохраняет изображение, блоки, повороты, непривязанный текст и историю.
Старые проекты версии1 читаются. **PDF/HTML** сохраняют геометрию размеченных
блоков; непривязанный текст добавляется отдельно. **TXT/DOCX** — линейная копия.
Шрифт печатный: расположение и угол воспроизводятся, имитация почерка не выполняется.
Автоматические координаты и транскрипцию необходимо сверять с оригиналом.

## Подключение локальной модели

В верхней строке выберите платформу и модель. Подключение запускается автоматически:
предыдущая модель Чтеца освобождается перед следующей загрузкой. При следующем запуске
восстанавливается последнее настроенное подключение. Статус показывает этап и результат.
**↻** обновляет каталог без сброса работающего подключения, **Подключить** повторяет попытку.

Модели LM Studio находятся через официальный `lms ls --llm --json`; GGUF Unsloth —
в папке моделей LM Studio и рядом с ранее выбранным файлом. Проекторы mmproj и известные
аудио/генеративные семейства исключаются. Можно указать GGUF или имя модели вручную
в **Настройки ИИ**. Веса автоматически не скачиваются.

### LM Studio

- Укажите ключ установленной локальной модели, например `google/gemma-4-e4b`.
  Этот ключ виден в LM Studio; это имя модели, а не API-ключ.
- Стандартный API: `http://127.0.0.1:1234/v1`.
- Чтец запускает установленное приложение и официальный `lms`, включает сервер
  и загружает модель с собственным идентификатором. При переключении выгружает
  только эту модель. Окно LM Studio остаётся открытым.
- При автозапуске распознавание и правки используют одну выбранную модель.
  Это предотвращает незаметную загрузку второй модели в память.

### Unsloth / Unsloth Studio

- Выберите существующий локальный **GGUF**. Для vision нужен совместимый
  `mmproj` рядом с моделью. Проверены установленные Gemma E4B и E2B.
- Стандартный управляемый API: `http://127.0.0.1:8890/v1`. Он отделён от
  уже открытого Unsloth Desktop на 8888. Порты двух систем должны различаться.
- Чтец запускает официальный `unsloth run --api-only` с отключёнными tools и
  Cloudflare, получает служебный ключ от своего CLI в память и определяет
  фактически загруженную модель через `/api/inference/loaded-models`.
- Никакие ключи Чтец не сохраняет в JSON или журнал. Официальный Unsloth может
  хранить свой ключ собственными средствами. Существующие чужие процессы
  и ключи не изменяются.
- Занятый порт не захватывается: выберите свободный порт или закройте свой
  ненужный сервер штатным способом.

Пути к CLI/приложению можно исправить в настройках. Для автозапуска используется
HTTP на 127.0.0.1; сетевые адреса запрещены. Старые настройки автоматически
переносятся в профиль LM Studio. Кнопка **Обновить список моделей** получает каталог установленных моделей без загрузки на сервер.

При переключении предыдущая модель Чтеца освобождается перед следующей загрузкой.
Unsloth работает в отдельном Windows Job Object: его дочерние процессы завершаются
вместе с Чтецом. Модели, загруженные пользователем вручную в других окнах, Чтец
не выгружает — освободите их перед запуском, если не хватает видеопамяти.
Отмена загрузки LM Studio дожидается завершения серверной операции и затем
выгружает модель: убийство CLI не отменяет загрузку на сервере. Если загрузка
превысила 10 минут, Чтец сохраняет контроль над ней и блокирует переключение до
автоматической выгрузки. Принудительное завершение Чтеца во время такой загрузки
может оставить модель в LM Studio; её можно выгрузить в самом LM Studio.

Подключение сервера и качество распознавания проверяются отдельно: правильный
HTTP-ответ ещё не означает точное чтение старой рукописи. Тесты приложения не
являются оценкой точности OCR.

Официальные протоколы:
[LM Studio](https://lmstudio.ai/docs/developer/openai-compat/chat-completions),
[Unsloth API](https://unsloth.ai/docs/basics/api).

Для локальных систем разрешены только `localhost` и loopback IP. Приложение отключает HTTP-прокси и
переадресации. Сам локальный сервер также должен быть настроен на **локальную**
модель: приложение не может узнать, пересылает ли сторонний сервер запросы дальше.
Инструменты модели, web search и cloud routing включать не требуется.
Ключ локального сервера хранится только в памяти до закрытия приложения. Остальные настройки —
в `.chtec/settings.json` текущей папки; путь можно задать переменной `CHTEC_CONFIG`.

## Облачные API

Поддерживаются OpenAI (Responses), Anthropic Claude (Messages), Google Gemini
(generateContent), DeepSeek, Alibaba Qwen и xAI Grok (OpenAI-совместимый Chat API).
Выберите поставщика → **Настройки ИИ** → введите его API-ключ → **Обновить список моделей**
→ выберите модель → **Сохранить и подключить**. Ключ вводите только в приложении.
Каталог доступен для вашего ключа и региона; фиксированный список моделей не зашит.

Для Alibaba Qwen выберите регион либо вставьте официальный HTTPS workspace endpoint
из консоли (`https://<workspace>.<region>.maas.aliyuncs.com/compatible-mode/v1`).
Ключи регионов различаются; при изменении адреса поле ключа очищается.

Облачный поставщик и адрес постоянно отображаются в интерфейсе. Распознавание,
уточнение фрагментов и правки используют выбранный API; автоматического ухода
с локальной модели в облако нет. Вызовы могут оплачиваться по тарифам поставщика.
Модели с заявленным отсутствием vision отклоняются при отправке изображения;
при неизвестных возможностях это указано в списке. Успех подключения к каталогу
ещё не подтверждает качество или поддержку OCR конкретной моделью.

Ключи облака сохраняются в `.chtec/settings-keys/*.dpapi`, зашифрованы Windows DPAPI
для текущей учётной записи. В JSON, документах и журналах ключей нет. При переносе
на другой компьютер ключ вводится заново; ошибка чтения одного ключа не сбрасывает
профили. Само приложение не управляет политиками хранения данных поставщиков.
Каталог ограничен общим сроком 45 секунд (CLI LM Studio — 25); отмена проверяется
между запросами. Текущий сетевой запрос завершается по тайм-ауту.

Проверки облачных адаптеров выполняются на синтетических подменённых ответах.
Для реального подключения необходимы действующий ключ, доступ к API и баланс.
Личные сканы не использовались для облачных проверок.

Официальные справочники:
[OpenAI](https://developers.openai.com/api/reference/resources/responses/methods/create),
[Anthropic](https://platform.claude.com/docs/en/api/overview),
[Gemini](https://ai.google.dev/api/models),
[DeepSeek](https://api-docs.deepseek.com/api/list-models/),
[Qwen](https://www.alibabacloud.com/help/en/model-studio/list-models),
[xAI](https://docs.x.ai/developers/rest-api-reference/inference/models).

## Работа с документом

1. Нажмите **Добавить файлы** или перетащите файлы в окно. Можно загрузить несколько
   источников в один документ. PDF и TIFF раскладываются на страницы.
2. Выберите страницу слева. Скан отображается рядом с редактируемым текстом;
   кнопки `+` / `−` меняют масштаб.
   Для удаления выбранной страницы нажмите **Удалить страницу** под списком или
   **Delete**, когда фокус в левой колонке. После подтверждения страница и её текст
   удаляются из рабочего документа; исходный файл остаётся на диске. Удаление во
   время обработки недоступно, отмены уже подтверждённого удаления пока нет.
3. Нажмите **Распознать страницу** или **Распознать всё**. На время операции редактор
   блокируется. Остановка действует между страницами; текущий запрос заканчивается
   ответом или тайм-аутом. Уже завершенные страницы сохраняются в текущем документе.
4. Сверьте текст и исправьте вручную. Модель помечает неразборчивые места по инструкции,
   но может ошибаться и без пометки. Проверяйте имена, даты, суммы и отрицания.
5. Для правки моделью введите запрос в поле под редактором. В отдельном окне сравните
   исходник и предложение. Предложение можно поправить вручную, применить или отклонить.
   Операция относится к текущей странице, не ко всему документу.
6. Нажмите **Предпросмотр и сохранение** (`Ctrl+S`). Просмотрите весь текст, выберите
   формат и путь. Для изменения текста закройте предпросмотр и вернитесь в редактор.
7. Сохраните **JSON-проект**, если хотите продолжить позже с исходниками и историей.
   Экспорт TXT/DOCX/PDF сам по себе не сохраняет рабочий проект.

`Ctrl+O` добавляет файлы. В редакторе работает обычный `Ctrl+Z`; кнопка отмены также
позволяет вернуться к тексту перед OCR/правкой модели. Хранятся последние 50 изменений
каждой страницы. После закрытия история доступна только в сохраненном JSON-проекте.
Встроенная история Qt отключена: кнопка, Ctrl+Z и контекстное меню используют одну
историю документа. Redo пока не предусмотрено.
Автосохранения пока нет: регулярно сохраняйте проект. При закрытии и создании нового
документа приложение предупреждает о несохраненном проекте.

## Масштабирование и уточнение рукописи

- Вращайте колесо над изображением для изменения масштаба (25–500% относительно
  масштаба по ширине). По возможности точка под курсором остаётся на месте.
- Зажмите левую кнопку и тяните страницу, если изображение не помещается в область
  просмотра. Это работает и для длинной страницы при исходном масштабе.
- Кнопки `+` / `−` также доступны. Масштаб просмотра не меняет исходный снимок и
  не влияет на обычный запрос распознавания всей страницы.

### Повторно прочитать выбранный участок

1. Нажмите **Выделить фрагмент** над сканом и обведите нужный участок левой кнопкой.
   В этом режиме левая кнопка выделяет область; после выделения снова работает перемещение.
2. В редакторе выделите неразборчивые слова, которые нужно заменить. Если выделения
   текста нет, результат будет предложен для вставки в текущую позицию курсора.
3. Нажмите **Прочитать фрагмент**. В модель отправляется отдельная обрезка, а не
   скриншот увеличенного окна. Для фото и TIFF используется исходное разрешение,
   для PDF заново растрируется выбранная область. Сохранённый preview имеет предел
   2400 px, но при доступном оригинале этот предел применяется **после** обрезки.
4. В окне предложения проверьте замену. Кнопка **Показать повторные чтения** раскрывает
   непосредственный ответ модели. Можно исправить текст справа, применить или отклонить.

Если оригинал отсутствует, используется изображение из JSON-проекта, что явно
указывается в предложении. Если доступный оригинал не совпадает с сохранённой страницей,
программа просит загрузить его заново, чтобы координаты соответствовали изображению.
Исходный файл не изменяется. Старые JSON-проекты остаются совместимыми.

### Автоматически уточнить страницу по частям

**Уточнить страницу по фрагментам** выполняет повторное чтение четырёх перекрывающихся
областей, затем просит модель сопоставить их с текущей расшифровкой. Это ограниченный
цикл: четыре OCR-запроса и один запрос текстового объединения. Модель не управляет
компьютером и не может бесконечно запрашивать увеличения. Границы неразборчивых слов
в исходном OCR неизвестны, поэтому просмотрены будут все четыре области страницы.
Кнопка доступна после появления текста; окончательная правка применяется только явно.

Остановка проверяется между запросами; текущий запрос заканчивается ответом или
тайм-аутом. При остановке исходный текст сохраняется. Многочастное уточнение может
занять несколько минут, показаны счётчик фрагментов и общее время ожидания.

Отдельная обработка фрагментов может помочь мелкому тексту занять больше визуальных
токенов модели. Простое растягивание пикселей не восстанавливает потерянные детали;
результат зависит от модели, фокуса снимка, почерка и контекста. Общий подход к
обработке изображений разного разрешения описан в
[Qwen2-VL](https://arxiv.org/abs/2409.12191). Это не обещание улучшения именно Gemma.
На реальном архивном фрагменте функция проверена с локальной Gemma, но чтение имён
и старой орфографии всё ещё содержит ошибки. Автоматические предложения всегда сверяйте.

## Форматы ввода и вывода

| Назначение | Поддерживается |
|---|---|
| Изображения | PNG, JPG/JPEG, TIFF/TIF, BMP, WEBP, GIF; все кадры многостраничных файлов |
| Сканы | PDF, включая PDF без текстового слоя |
| Продолжение работы | JSON-проект Чтец версии 1 |
| Текстовый экспорт | TXT (UTF-8), MD, HTML (экранированный текст) |
| Документы | DOCX, PDF с выделяемым текстом и Unicode-шрифтами |
| Рабочий проект | JSON: нормализованные изображения, текст, история |

AVIF доступен, если текущая сборка Pillow содержит декодер. Для HEIC/HEIF установите
кодек и перезапустите Чтец:

```powershell
.\.venv\Scripts\python.exe -m pip install -e ".[heic]"
```

Это текстовая транскрипция: расположение элементов, факсимиле, таблицы и подписи
в точности не восстанавливаются. Выходной PDF — новая текстовая копия, а не исходный
скан с наложенным OCR-слоем. Предпросмотр показывает весь текст и границы исходных
страниц, а не точный печатный макет DOCX/PDF. Markdown экспортируется как содержимое
редактора; автоматического восстановления разметки нет.

Пределы: 100 MiB на входной файл и JSON-проект, 200 страниц в документе,
60 MiB на сумму нормализованных изображений,
40 млн пикселей на изображение; перед OCR длинная сторона уменьшается до 2400 px.
Оригиналы не меняются; JSON хранит нормализованные копии. PDF с паролем нужно
предварительно сохранить без шифрования. Большие документы лучше делить на части.

## Архитектура и расширения

ООП: `Page`/`Document` описывают состояние; `DocumentService` управляет OCR;
`LanguageModel` задает контракт; `LocalModel` реализует локальный HTTP-адаптер.
`Importer`/`Exporter` — абстрактные стратегии, `FormatRegistry` разрешает расширения.
Qt-слой работает с сервисами, тяжелые операции выполняет `Worker` в `QThread`.
Поток обработки сообщает результаты; состояние редактора меняется в UI-потоке.

Новый формат можно добавить отдельным установленным Python-пакетом без изменения UI.
Пример экспортера CSV — `examples/csv_plugin/`. Установка:

```powershell
.\.venv\Scripts\python.exe -m pip install --no-build-isolation ./examples/csv_plugin
```

Или зарегистрируйте обработчик прямо в `chtec/formats/__init__.py`.
Плагин реализует `read(path) -> list[Page]` или `write(document, path) -> None`,
задает `extensions` и `label`, а функция `register(registry)` регистрирует его.
В `pyproject.toml` плагина объявляется entry point группы `chtec.formats`.
Для многостраничного импортера реализуйте также `page_count(path) -> int`, чтобы
проверять оставшийся лимит страниц до декодирования.
Один формат не может незаметно заменить другой. Плагины — исполняемый доверенный
Python-код: устанавливайте только проверенные пакеты. Их зависимости устанавливаются
отдельно. Файлы пользователя не загружаются как Python-плагины.

## Разработка и проверка

```powershell
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m ruff check .
.\.venv\Scripts\python.exe -m compileall -q chtec
```

Тесты HTTP создают временный сервер только на `127.0.0.1`. Если среда запрещает
локальные соединения, предоставьте разрешение тестовому процессу; не отключайте
проверки. GUI-тесты используют Qt offscreen.

Для ручной приемки: загрузите реальную рукопись с известной транскрипцией,
распознайте, сравните посимвольно, проверьте правку и отмену, экспортируйте все
форматы и откройте их во внешних программах. Затем отключите сервер и проверьте
понятную ошибку без потери уже введенного текста.
